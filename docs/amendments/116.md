# Bounded architecture reviews

Scheduled review briefs now distinguish planning from execution. Both focus on
recorded completed changes and affected modules, with configured static analysis
as evidence. Execution produces a documentation-only architecture baseline and
ranked findings. Unverified checkpoint references remain evidence to investigate,
not assumed merge bases. Public artifacts use repository-derived descriptions
and public work references.

Review follow-ups are limited to small, independently specified improvements.
Broader architectural proposals go to the owner as recommendations. Agents can
attach at most three incoming follow-up links to each scheduled review. Existing
links count even when their children are complete or were filed by people. People
retain authority to add or remove links; removing a link frees a slot. Other
relation kinds and ordinary parent tickets keep their existing behavior.

Related creation checks the parent's lease, creates the child, records its
dependencies and attaches its parent link in one write transaction. Failed
requests leave no child or partial history, and events publish after commit.
The same quota applies to links between existing tickets.

Spec-bearing agent follow-ups of autonomous reviews inherit autonomy and enter
Ready at the top of Todo. Children are ordinary tickets, not scheduled reviews.
Without a spec, the existing refinement flow applies. Queue placement does not
bypass dependency eligibility, capacity limits or work already in progress.

Ordinary design and build briefs conditionally direct workers to the checkout's
architecture baseline and listed shared abstractions. The board does not inspect
repository files to render that guidance.
