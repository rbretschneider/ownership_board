# Architecture check interval and checkpoint

Each repo has a `health_check_every` setting: the number of merges between
architecture health checks. It accepts whole numbers from 0 to 50, where 0 turns
the check off. Existing and new repos default to 8. The bounds are enforced in
the domain layer (`Repo.Restyle`), not by a SQL constraint.

Two checkpoint columns record where the last check ended:
`health_checked_through_ticket` (the last merged ticket id covered) and
`health_checked_at`. Both are null until the first check. They are exposed
read-only in the repo API and cannot be set over HTTP; only the store method
`RecordHealthCheck` writes them, for the code that files the checks.

Only a signed-in person can change the interval (`PATCH /api/v1/repos/{id}`);
agent tokens receive 403. A provider sync never touches either setting.
