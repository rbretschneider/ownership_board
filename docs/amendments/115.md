# Scheduled architecture reviews

Repository merge intervals now enqueue architecture reviews automatically.
Completing an ordinary ticket records its first completion in a repository-local
sequence. When enough completed tickets remain beyond the last consumed sequence,
the board creates an autonomous story in Ready with an approved initial spec and
places it first in the queue. A zero interval disables scheduling.

An open review defers further filings while ordinary completions accumulate.
Completing the review evaluates that backlog immediately. Reviews themselves do
not contribute to the interval. The normal autonomous claim limit still controls
when queued work starts.

Ticket creation, timeline history and checkpoint advancement commit with the
originating completion. Events and the existing autonomous notification follow
commit. No provider request or model call is needed.

Generated specs list every covered ticket in merge order and include an
architecture review rubric. Titles are flattened and escaped as data. A commit
work link on the preceding checkpoint can supply a recorded commit reference;
it does not prove a merge base. Without that reference, the baseline is unknown.

Migration 0012 initializes historical ordering from the earliest recorded Done
transition, falling back to the lane-change time and ticket ID. Equal-time
historical ordering is necessarily approximate. Future ordering uses persisted
sequences. Moving a ticket to another repository clears its old sequence; a later
completion records a position in the destination repository.

Ticket responses expose the read-only `is_health_check` marker. Creation and edit
requests cannot set it. Internal generation preserves complete large ranges while
external title and document limits continue to apply to user input.
