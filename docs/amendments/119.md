# Machine identity and health reports

Enrollment and health reporting use dedicated routes with Ed25519 identities.
The existing browser and bearer-token access rules remain separate. Exact raw
request bytes are verified before parsing; endpoint paths and credential headers
have canonical representations. Timestamps bound request age but do not prevent
replay within that interval. Transport confidentiality remains necessary.

Enrollment inserts the pending identity and consumes a hashed pairing code in
one SQLite write transaction. Metadata validation precedes consumption. A unique
public-key constraint prevents identity reuse, including after revocation. A
bounded per-address limiter protects the anonymous endpoint.

Reports validate a complete facts schema while older registry records retain
their original read contract. Migration 0014 adds running-job telemetry, free
disk, and append-only toolchain history. Administrative updates and report
updates touch separate columns. Lifecycle is checked again inside the report
transaction so a completed revocation prevents subsequent updates. A report and
its toolchain-change event either both commit or both roll back. Rolling back
the migration removes report additions while retaining the previous registry.

Connectivity is computed from approval and the latest server heartbeat time.
There is no background sweep or stored offline state. Human list responses
capture one clock value for consistent connectivity calculations.

Capability suggestions are used at enrollment only. Reports remain untrusted
observations and cannot alter owner-selected scheduling controls or authorize
job operations. Human-only history pagination makes toolchain changes visible
without introducing a new UI.

Notifications use the existing transport directly with fixed content, after a
successful enrollment commit. Each committed enrollment makes one invocation;
transport failures are logged safely. There is no transactional notification
outbox or delivery retry. See the machine protocol in [api.md](../api.md) for
wire encoding, validation limits, status codes, and capability rules.
